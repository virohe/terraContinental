# Compatibility

## Tectonic (absorbed, 2026-10-30)

Terra Continental's terrain started as Tectonic 3.0.28's (MIT, attributed in
`resourcepacks/terrain/NOTICE.txt`) and is its own now. It is declared **incompatible** with Tectonic: both would override
the same overworld files and seed the same noises. It also stretches the overworld to y -512..1,264
(`dimension_type/overworld`), for every world type that uses `minecraft:overworld`, and requires
Lithostitched (the base terrain uses its density-function types).

## Global namespace overrides

Terra Continental overrides four density functions in the **`minecraft` namespace**:

- `data/minecraft/worldgen/density_function/overworld/continents.json`
- `data/minecraft/worldgen/density_function/overworld/erosion.json`
- `data/minecraft/worldgen/density_function/overworld/ridges.json`
- `data/minecraft/worldgen/density_function/overworld/depth.json`

### What this means

These overrides are **intentional** — they are how the mod rewires Minecraft's
noise router without requiring a custom dimension preset.

**All dimension presets are affected.** The vanilla Default, Large Biomes, and
Amplified presets all reference these same density functions, so installing this
mod rewrites terrain for all of them.

**Vanilla Default worlds become Terra Continental worlds.** If a player creates a
new world using the default preset with this mod installed, they will get Terra
Continental terrain, not vanilla terrain.

### Conflicts with other worldgen mods

Other worldgen mods that override the same four files (Tectonic, Terralith,
William Wyther's Expanded Ecosphere, etc.) will **conflict silently** by
datapack load order. Whichever mod's datapack is loaded last wins. There is no
error or warning; the losing mod's overrides are simply ignored.

If you are building a modpack that includes Terra Continental alongside another
worldgen mod, you must decide which mod's continents/erosion/ridges/depth
overrides should win and configure datapack load order accordingly, or use a
datapack that explicitly merges both.

## World types (0.9.0)

Three types are added: `terra_continental:large_biomes`, `terra_continental:temperate` and
`terra_continental:climates`, added to the `minecraft:normal` world-preset tag. Client mixins put
them first on the World Type button, then vanilla's Default, then every other type, and make a fresh
Create World screen start on TC: Large Biomes (vanilla hard-codes Default there). `WorldPresets.fromSettings`
recognises the TC noise settings, so "Re-Create" names those worlds' types. Vanilla's Default is untouched.
`biomeswevegone:village/swamp` is added to `#minecraft:village` (optional entry).

`noise_settings/overworld_large.json` and `overworld_climates.json` are copies of the terrain pack's
`minecraft:overworld` noise settings, changed only
in `noise_router.temperature` and `noise_router.vegetation`, and generated by
`tools/make_world_types.py` from `resourcepacks/terrain`.

**WorldWeaver**: on dedicated servers its `force_default_world_preset` (`config/wover/main.json`)
replaces every world's type with its own; turn it off to use these types.
